# 设计说明（DESIGN）

这份文档记录 quest-system 的关键取舍与实测过的坑。改代码前先读一遍。

## 1. 状态机

任务块是账本里的 markdown 段（`## Q###` 开头），状态只有五种，写死在引擎里：

```
在架 ──accept──▶ 已交·待验收 ──set(完成)──▶ 完成
  ▲                    │
  └──set(在架)·退回◀───┘        完成/看答案过关 = 通过（计入 done）
  在架 ──set(跳过)──▶ 跳过      跳过 ≠ 通过；节点换等价题再来
```

- 「在架」判定 = 全账本里唯一一个状态为在架的块。`issue` 见到在架直接返回它（防堆积）。
- 评语追加不覆盖：退回重做会有第二轮评语，用「｜再评：」拼接。

## 2. 为什么账本用 markdown 而不是 SQLite

- 账本要被**人和 agent 直接读**：手机上看、cron 里 cat、agent 当 prompt 塞。
- git diff 就是变更审计：每次 issue/accept/set 一个提交，天然时间线。
- 解析只要一个正则；状态字段写错最多丢一条，git checkout 就回来。
- 什么时候该换掉：任务数过千或要并发写。届时把 `blocks()/write_log()` 换实现即可，接口不动。

## 3. 引擎/题库分离

`engine.py` 只管状态机，题目全部在 `bank.py`（或环境变量 `QUEST_BANK` 指定的模块）。
接口一个函数：`next_task(items) -> dict | None`。换题库不动引擎，反之亦然。

## 4. 网页为什么是 monkey-patch 而不是独立服务

- 目标设备 4GB 内存，能不多一个进程就不多一个；
- 门户已有鉴权/隧道/nginx，新开端口 = 白名单+隧道参数+nginx 三处同改（见用户基建约定）；
- 钩子模块声明依赖（check_auth/shell/esc/_send/_unauth），门户不满足就接不上，宁缺勿歪。

## 5. 点评 agent 的实测坑

- `hermes -z` 没有 `--workdir` 参数——传了 argparse 直接退出且 stderr 被吞，表现为
  「eval 文件只有一行启动提示」。教训：**接新 agent 命令先手动跑一遍再接进 Popen**。
- agent 运行环境 ≠ 系统 python3：依赖装在 agent 自己的解释器里（本机是
  `~/.hermes/tools/python-3.14*/bin/python3`）。
- 评语里要求 agent「跑不动就写无法验证」，否则它会凭描述放行。
- agent 用 `{engine}` 绝对路径调 `engine.py set`，别依赖它的 cwd。

## 6. 6h 口径与计时

- 计时器只认「专注时间」：暂停/记账是两个动作，记账才进账本头部。
- 系数 = 实际专注小时 ÷ 6。**只看各域趋势，不看绝对值**——出题人对 6h 的估计本身有误差棒。

## 7. 隐私模型

公开仓库只含代码与模板。真实账本（做了什么、用时曲线、评语）是隐私，留在自托管机。
`data/` 里的示例全部是编造数据；README 不出现真实姓名、学校、实习单位、内网 IP。

## 8. 兼容性

- 目标机 Python 3.8（Ubuntu 20.04 系统投喂）：f-string 不嵌套同类引号、无 dict `|` 合并。
- 全部提交前 `python3 -m py_compile` 过一遍。
